fix(push): 推送成功后别报失败 —— inherit 模式下 execFileSync 返回 null

用户跑 npm run push，git 明明打出了成功标志：
  * [new branch]      main -> main
  branch 'main' set up to track 'origin/main'.
脚本却报「✗ 推送失败」，还把用户往认证问题上带。

根因：git() 里
    return execFileSync("git", ..., { stdio: "inherit" }).trim();
在 stdio:'inherit' 下 execFileSync 返回 null（输出直接进了终端，Node 不捕获），
.trim() 于是抛 TypeError，被 catch 当成"推送失败"。
也就是说：推送是成功的，是我自己的后续代码崩了，然后误报成 git 失败。

上一个 bug（git remote get-url 抛错）让我把注意力放在"失败路径要可读"，
却漏了这条"成功路径被打成失败"的反向错误 —— 它更糟：会让人去做完全无关的排查。

修法：
- 返回值归一化：typeof output === "string" ? output.trim() : ""
  （inherit 模式没有可捕获的输出，空串才是"命令成功"的正确表达）
- inherit 模式失败时 stderr/stdout 都是 undefined，退回「退出码 N」而不是一句空话

新增 test/push-git.test.mjs（12 项）：直接测真 git() 函数。
用猴补丁换掉 execFileSync 再 import，断言的是真代码而不是复制品。
覆盖 inherit 返回 null/undefined、捕获模式 trim、失败时带出 git 自己的 stderr、
EPERM 给出可照做的命令。

为什么之前的 26 项没抓到：push-logic 那套把整个 git() 换成假的，
专注于决策分支 —— 真 git() 自己一行都没被测到。这次补上这个缺口。
已做变异测试：还原成有 bug 的写法，4 项立刻报红（含真机崩点那一项）。

package.json 的 test / test:push / verify 与 CI 一并接上。
